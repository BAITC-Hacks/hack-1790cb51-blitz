# ATLAS · HackAlem AI

**Анализ организационной структуры и функционала. Команда Blitz.**

ATLAS сравнивает комплекты документов до и после реорганизации: определяет изменение подразделений, сопоставляет функции, выявляет кандидатов на потерю и дублирование обязанностей, отмечает потенциальные конфликты интересов. Каждый существенный вывод сопровождается исходными фрагментами. Сотрудник проверяет выводы и экспортирует аналитическое заключение.

Это работающий локальный хакатонный прототип, а не статический макет. Загрузка, анализ, история, решения проверяющего и экспорт связаны с Python API и сохраняются в SQLite.

## Что доступно

- Проекты с отдельными комплектами «до» и «после» и историей успешных запусков.
- Загрузка DOCX, текстового PDF, XLSX, TXT и CSV; сохранение оригиналов и адресов фрагментов.
- GPT-анализ через OpenAI Responses API: извлечение функций, смысловое сопоставление и объяснимые замечания.
- Локальный режим без API-ключа и детерминированный демонстрационный комплект.
- Обзор с реальной статистикой, поиск и фильтры, карта преемственности подразделений.
- Боковая панель источника с выделенным пунктом и ручным исправлением разметки.
- Подтверждение/отклонение замечаний и комментарии, сохраняемые в заключении.
- HTML и Markdown-отчёты, CSV-таблица; печать отчёта в PDF средствами браузера.
- Адаптивный интерфейс, мобильные карточки сопоставления, управление с клавиатуры и модальные окна с удержанием фокуса.

## Быстрый запуск с Docker

Требуется Docker Engine / Docker Desktop с Compose v2.

```powershell
# Windows PowerShell, из корня репозитория
Copy-Item .env.example .env
docker compose up --build
```

В Linux/macOS: `cp .env.example .env`, затем та же команда Compose.

- Приложение: **http://localhost:5173**
- Swagger API: http://localhost:8000/docs
- Health-check: http://localhost:8000/api/health

При первом запуске автоматически создаётся демо-проект. Для демонстрации ключ не нужен. Данные хранятся в Docker volume `atlas_data` и сохраняются после `docker compose down`. Не используйте `down -v`, если нужно сохранить проекты.

Для GPT заполните `OPENAI_API_KEY` в корневом `.env` и пересоздайте backend: `docker compose up -d --force-recreate backend`. Не добавляйте ключ в Git.

## Локальный запуск без Docker

Требования: **Python 3.12+**, **Node.js 22.12+**, npm.

Windows, два терминала:

```powershell
# Терминал 1
cd backend
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
Copy-Item .env.example .env
# При необходимости добавьте OPENAI_API_KEY в backend/.env
.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

```powershell
# Терминал 2
cd frontend
npm ci
npm run dev -- --host 127.0.0.1
```

Для удобства есть `./scripts/dev.ps1`: устанавливает зависимости и запускает оба сервера. Повторный запуск без установки — `./scripts/dev.ps1 -SkipInstall`. Остановка — Ctrl+C; логи лежат в `data/`. Скрипт не перезаписывает `.env` и не останавливает чужие процессы на занятых портах.

Linux/macOS:

```bash
cd backend
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock.txt
cp .env.example .env
.venv/bin/uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
# В другом терминале: cd frontend && npm ci && npm run dev
```

Vite проксирует `/api` на backend. База находится в `backend/data/atlas.sqlite3` при запуске из папки `backend`.

## Подключение GPT

Локально заполните `backend/.env`, для Docker — корневой `.env`:

```dotenv
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=gpt-5-mini
SEED_DEMO=true
```

Модель выбрана для структурированного извлечения и сопоставления. Её можно заменить на доступную вашему API-проекту модель с поддержкой Responses API и Structured Outputs. Ключ остаётся на сервере. После изменения `.env` перезапустите backend. Статус подключения виден в настройках интерфейса.

GPT получает извлечённый текст загруженных документов; используются API-кредиты. Запросы выполняются с `store=false`. Автоматическое создание демо-проекта **не вызывает GPT**. Чтобы проверить модель на демо, нажмите «Повторить анализ» и выберите GPT. Если модель недоступна или ответ не проходит проверку источников, приложение показывает ошибку, а не подменяет результат локальным.

## Как проверить задание хакатона

Откройте демо-проект «Реорганизация операционного блока». В локальном режиме ожидаются:

| Показатель | Значение |
| --- | --- |
| Документы | 4 до, 5 после |
| Подразделения | 4 до, 5 после |
| Функции | 17 до, 18 после |
| Сопоставлено исходных функций | 15 из 17, 88% |
| Возможные потери | 2 |
| Пересечения функций | 2 |
| Потенциальные конфликты | 1 |

Комплект расположен в `backend/examples/`, также скачивается из раздела «Документы». Данные синтетические. Результаты рассчитываются из файлов при каждом запуске. GPT может сопоставить функции иначе: смысловые выводы проверяются человеком.

Полный сценарий выступления и конкретные контрольные пункты: [docs/demo.md](docs/demo.md).

## Проверки

```powershell
cd backend
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\ruff.exe check app tests
```

```powershell
cd frontend
npm ci
npm run build
npm run format:check
```

Тесты проверяют загрузку и извлечение, контрольные изменения, точность источников, ручные решения, инвалидирование результата, экспорт, отсутствие ключа, строгий контракт Responses API, семантические соответствия и отклонение выдуманных ссылок. OpenAI в автоматических тестах заменён контролируемыми ответами, кредиты не расходуются.

GitHub Actions выполняет Python-тесты, сборку React, проверку форматирования и запуск Docker Compose с запросами к UI и API. Для реального GPT-вызова нужен отдельный ручной прогон с ключом.

## Структура

```text
backend/
  app/                 API, парсинг, GPT, анализ, хранение, экспорт
  examples/            Контрольные документы до и после
  tests/               Проверки анализа и API-контракта
  requirements.lock.txt
frontend/
  src/pages/           Экраны рабочего пространства
  src/components/      Диалоги, источники и общие элементы
  src/styles.css       Адаптивная визуальная система
  nginx.conf           Раздача клиента и /api-прокси
scripts/dev.ps1        Локальный запуск Windows
docs/                 Архитектура и сценарий демонстрации
docker-compose.yml    Frontend + backend + постоянный volume
```

Подробнее о границах модулей, данных и проверке ссылок: [docs/architecture.md](docs/architecture.md).

## Ограничения

Выводы рекомендательные. «Преемник не найден» не доказывает утрату функции; проверьте полноту комплекта. Проценты в локальном сопоставлении — сходство формулировок, не уверенность GPT. Карта структуры показывает преемственность, а не официальную иерархию.

Поддерживаются текстовые PDF, но не OCR сканов и не старые DOC/XLS. Максимум: 10 МБ на файл, 40 документов, 600 функций и 150 страниц в одном PDF. Для GPT: 450 абзацев/160 000 символов на документ и 240 000 символов функций на сопоставление. Внешние нормативные проверки и бенчмаркинг не реализованы.

Приложение рассчитано на локальное доверенное рабочее пространство без авторизации. Для публичного размещения необходимы аутентификация, разграничение проектов и защита API. SQLite используется одним процессом backend; масштабирование требует очереди задач и серверной БД.
