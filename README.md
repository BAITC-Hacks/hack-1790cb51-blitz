# ATLAS · HackAlem AI

**Анализ организационной структуры и функционала. Команда Blitz.**

ATLAS сравнивает комплекты документов до и после реорганизации: определяет изменение подразделений, сопоставляет функции, выявляет кандидатов на потерю и дублирование обязанностей, отмечает потенциальные конфликты интересов. Каждый существенный вывод сопровождается исходными фрагментами. Сотрудник проверяет выводы и экспортирует аналитическое заключение.

Это работающий локальный хакатонный прототип, а не статический макет. Загрузка, анализ, решения проверяющего и экспорт связаны с Python API и сохраняются в SQLite.

## Что доступно

- Три этапа: загрузка двух документов → анализ → результаты. Без аккаунтов, списка проектов и истории в интерфейсе. В каждом документе может быть несколько подразделений.
- Замена файла после успешного чтения нового; при ошибке прежний файл остаётся. Старые проекты с несколькими файлами сохраняются: перед новым анализом оставьте по одному на сторону.
- Загрузка DOCX, текстового PDF, XLSX, TXT и CSV; сохранение оригиналов и адресов фрагментов.
- GPT-анализ через OpenAI Responses API: извлечение функций, смысловое сопоставление и объяснимые замечания.
- Единственная модель анализа — GPT-5. Запуск только по нажатию «Начать анализ».
- Единый экран результатов: замечания, функции, подразделения и заключение. Поиск, фильтры и исходные цитаты.
- Боковая панель источника с выделенным пунктом и ручным исправлением разметки.
- Подтверждение/отклонение замечаний и комментарии, сохраняемые в заключении.
- HTML и Markdown-отчёты, CSV-таблица; печать отчёта в PDF средствами браузера.
- Адаптивный интерфейс, мобильные карточки сопоставления, управление с клавиатуры и модальные окна с удержанием фокуса.

## Быстрый запуск с Docker

Требуется Docker Engine / Docker Desktop с Compose v2.

```powershell
# Windows PowerShell, из корня репозитория
Copy-Item .env.example .env
docker compose up --build
```

В Linux/macOS: `cp .env.example .env`, затем та же команда Compose.

- Приложение: **http://localhost:5173**
- Swagger API: http://localhost:8000/docs
- Health-check: http://localhost:8000/api/health

При первом открытии создаётся пустое сравнение без демо-данных. Для анализа нужен API-ключ с доступом к GPT-5. Данные хранятся в Docker volume `atlas_data` и сохраняются после `docker compose down`. Не используйте `down -v`, если нужно сохранить проекты.

Для GPT заполните `OPENAI_API_KEY` в корневом `.env` и пересоздайте backend: `docker compose up -d --force-recreate backend`. Не добавляйте ключ в Git.

## Локальный запуск без Docker

Требования: **Python 3.12+**, **Node.js 22.12+**, npm.

Windows, два терминала:

```powershell
# Терминал 1
cd backend
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
Copy-Item .env.example .env
# При необходимости добавьте OPENAI_API_KEY в backend/.env
.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

```powershell
# Терминал 2
cd frontend
npm ci
npm run dev -- --host 127.0.0.1
```

Для удобства есть `./scripts/dev.ps1`: устанавливает зависимости и запускает оба сервера. Повторный запуск без установки — `./scripts/dev.ps1 -SkipInstall`. Остановка — Ctrl+C; логи лежат в `data/`. Скрипт не перезаписывает `.env` и не останавливает чужие процессы на занятых портах.

Linux/macOS:

```bash
cd backend
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock.txt
cp .env.example .env
.venv/bin/uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
# В другом терминале: cd frontend && npm ci && npm run dev
```

Vite проксирует `/api` на backend. База находится в `backend/data/atlas.sqlite3` при запуске из папки `backend`.

## Подключение GPT

Локально заполните `backend/.env`, для Docker — корневой `.env`:

```dotenv
OPENAI_API_KEY=ваш_ключ
```

Приложение использует только `gpt-5` через Responses API и Structured Outputs. Переключателя модели и локального анализа нет; `OPENAI_MODEL` больше не используется. Ключ остаётся на сервере. После изменения `.env` перезапустите backend. Статус настройки ключа виден в интерфейсе; фактический доступ проверяется запросом при анализе.

GPT-5 получает извлечённый текст загруженных документов; используются API-кредиты. Запросы выполняются с `store=false`. Переход на этап анализа **не вызывает GPT**. Запрос отправляется только по кнопке «Начать анализ». Все новые запуски используют GPT-5. Если ключ отсутствует, сервер не запускает анализ. Ошибки доступа, баланса или сети не подменяются локальным результатом.

Подразделения выбираются по ID из каталога исходных заголовков; сервер подставляет название из документа. Модель не генерирует названия, поэтому сокращение или перефразировка больше не обрывает анализ. Если заголовка нет, используется имя файла с предупреждением и возможностью ручной правки. Пропуски и повторы ID разметки запускают одну повторную проверку GPT-5. Старые записи в базе не удаляются, но интерфейс показывает только текущее сравнение.

## Как пользоваться

1. **Загрузка документов.** Добавьте один файл «до» и один «после». При необходимости откройте «Проверить текст». Нажмите «Перейти к анализу».
2. **Анализ.** Проверьте выбранные файлы и нажмите «Начать анализ». Видны прогресс и текущая операция. По завершении откроются результаты. При ошибке можно повторить запуск.
3. **Результаты.** Просмотрите замечания и исходные цитаты, сопоставление функций и изменения подразделений. Подтвердите или отклоните замечания; сохраните заключение через «Экспорт» или печать в PDF.

Текущее сравнение сохраняется при обновлении страницы в том же браузере. «Новое сравнение» открывает пустую пару без удаления прежних данных из базы; перед этим сохраните нужный отчёт, поскольку переключения между сравнениями в интерфейсе нет. Сгенерированные примеры и скрипты подготовки документов убраны из репозитория. Тестовые данные существуют только внутри автотестов.

## Проверки

```powershell
cd backend
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\ruff.exe check app tests
```

```powershell
cd frontend
npm ci
npm run build
npm test
npm run format:check
```

Тесты проверяют загрузку и извлечение, контрольные изменения, точность источников, ручные решения, инвалидирование результата, экспорт, отсутствие ключа, запрет удалённых режимов, фиксированную GPT-5, строгий контракт Responses API, каталог подразделений и повторную проверку неполной разметки. OpenAI в автоматических тестах заменён контролируемыми ответами, сеть блокируется, кредиты не расходуются. Эти тесты проверяют приложение, а не качество самой модели.

GitHub Actions выполняет Python-тесты, тесты переходов трёх этапов, сборку React, проверку форматирования и запуск Docker Compose с запросами к UI и API. Для реального GPT-вызова нужен отдельный ручной прогон с ключом.

## Ограничения

Выводы рекомендательные. «Преемник не найден» не доказывает утрату функции; проверьте полноту комплекта. Проценты ближайших фрагментов — сходство формулировок, не уверенность GPT и не правило принятия соответствия. Все соответствия и потенциальные риски определяет GPT-5. Карта структуры показывает преемственность, а не официальную иерархию.

Поддерживаются текстовые PDF, но не OCR сканов и не старые DOC/XLS. Ограничения загрузки: 10 МБ на файл, один документ «до» и один «после», 150 страниц в одном PDF, 4 000 строк и 600 000 символов в файле. Лимитов GPT-анализа на 450 абзацев, 600 функций и общий объём текста больше нет: сервер автоматически обрабатывает документы частями, без обрезки текста. Каждая часть «до» сопоставляется со всеми частями «после»; риски проверяются внутри частей и между каждой парой частей «после». Это увеличивает время и расход API-кредитов, при росте обеих сторон число запросов может расти квадратично. Очень длинный отдельный абзац/строку (более 140 КБ UTF-8 с метаданными) нужно разбить на абзацы. Выводы модели требуют проверки человеком; сложные зависимости сразу между многими частями могут быть пропущены. Внешние нормативные проверки и бенчмаркинг не реализованы.

Приложение рассчитано на локальное доверенное рабочее пространство без авторизации. Для публичного размещения необходимы аутентификация, разграничение проектов и защита API. SQLite используется одним процессом backend; масштабирование требует очереди задач и серверной БД.
