# Архитектура ATLAS

ATLAS — локальный прототип для одного доверенного рабочего пространства. React отвечает за навигацию и проверку результатов, FastAPI — за обработку документов и анализ, SQLite — за сохранение данных. В Docker клиент раздаётся Nginx; `/api` проксируется в FastAPI. Отдельная PostgreSQL из исходного шаблона заменена на реально используемую SQLite: для хакатонного сценария не нужен отдельный сервис базы.

## Поток данных

```text
DOCX / PDF / XLSX / TXT / CSV
  → извлечение точного текста и адреса фрагмента
  → автоматическая разметка + ручные исправления
  → GPT: извлечение подразделений и функций
  → GPT: смысловые соответствия и потенциальные риски
  → проверка JSON, полноты и идентификаторов источников
  → таблица функций + изменения подразделений + замечания
  → проверка сотрудником → HTML / Markdown / CSV / печать PDF
```

Анализ выполняется только через GPT-5. Без API-ключа запуск запрещён; локальной подмены нет. Интерфейс содержит три этапа: загрузка, анализ, результаты. Пустое сравнение создаётся автоматически, текущее сравнение восстанавливается по ID в localStorage. Демо-данные и публичные маршруты их создания и скачивания удалены. GPT-5 запускается только по явному нажатию «Начать анализ».

## Серверные модули

| Модуль | Ответственность |
| --- | --- |
| `parser.py` | Извлечение текста, ограничение размера, адреса фрагментов, исходная разметка |
| `ai.py` | OpenAI Responses API, строгие JSON-схемы, обработка отказов и проверка ссылок |
| `analysis.py` | Сопоставление, источники, классификация изменений, статистика |
| `storage.py` | Транзакции SQLite, сериализация документов и результатов |
| `main.py` | API, загрузка, фоновые задания, история, решения проверяющего |
| `report.py` | Экспорт с экранированием HTML и защитой CSV от формул |

## Прослеживаемость

У фрагмента есть стабильный ID внутри документа. Ссылка на источник состоит из ID документа и ID фрагмента. Цитаты берутся из сохранённого извлечённого текста, а не генерируются моделью. DOCX использует номер абзаца, PDF — страницу и строку, XLSX — лист и строку. Номер пункта сохраняется, если он присутствует в извлечённом тексте.

GPT возвращает только соответствия существующих ID и текст объяснения. Сервер проверяет, что все исходные функции учтены, все ссылки существуют и риск имеет минимум два источника. При извлечении функции модель выбирает ID подразделения из ограниченного JSON Schema enum (или const для одного варианта). Каталог содержит названия из исходных заголовков (до 180 символов); имя файла доступно только при отсутствии заголовков. Сами названия не генерируются. Заголовок всегда закреплён за своим названием и не считается функцией; ручная разметка имеет приоритет. Если заголовки не обнаружены, сохраняется предупреждение о названии из файла. Необычные заголовки можно уточнить вручную. Эти проверки предотвращают вымышленные названия и ссылки, но не гарантируют правильность смыслового вывода: он подлежит проверке человеком.

Ручная разметка имеет приоритет над GPT. Изменение или удаление документа сбрасывает текущий результат и увеличивает редакцию проекта. Прежние записи сохраняются в базе для совместимости, но интерфейса истории, аккаунтов и переключения проектов нет. Во время анализа изменение документов и решений заблокировано транзакционной проверкой состояния. При перезапуске сервера незавершённые задания переходят в состояние ошибки и могут быть запущены повторно. Если повторный анализ завершился ошибкой, старый результат не отображается как новый. Кнопка нового сравнения не удаляет прежние пользовательские данные.

## GPT

Модель закреплена в коде: `gpt-5`; `OPENAI_MODEL` не используется. Используется `POST /v1/responses`, `text.format=json_schema`, `strict=true`, `store=false`, `reasoning.effort=low`.

Документы размечаются последовательными частями до 120 фрагментов. Последний заголовок предыдущей части передаётся явно, ID и цитаты не меняются. Для небольшого каталога доступен весь список подразделений; при более 200 заголовках или 24 КБ JSON — заголовки текущей части и предыдущий заголовок, чтобы не превышать ограничения enum в JSON Schema. Для преамбулы без заголовка в части доступен первый заголовок документа. При пропусках, повторах или неверных ID разметки выполняется одна повторная проверка текущей части. Ручные исправления сохраняются; новая разметка применяется только после успешной проверки всех частей.

Сопоставление разбивается на части до 120 функций «до» и 240 «после». Дополнительно применяется бюджет 96 КБ UTF-8 сериализованного текста на часть (консервативная оценка, не точный подсчёт токенов). Отправляются ID, текст и подразделение; адрес цитаты берётся сервером из оригинала, а не повторяется во всех запросах. Одиночный фрагмент может превышать бюджет части, но не 140 КБ с метаданными; более длинный абзац нужно разделить без потери текста. Общих лимитов на число фрагментов/функций на уровне GPT нет; ограничения загрузчика остаются.

Каждая часть «до» сравнивается со всеми частями «после». Отсутствие преемника определяется только после завершения всех сравнений. Риски внутри каждой части «после» проверяются при первом сравнении, затем отдельно проверяется каждая пара частей «после». Если частей `B` и `A`, сопоставление и проверка рисков требуют `B*A + A*(A-1)/2` запросов. Совпадения объединяются по ID; одинаковые риски — по виду и набору источников, с сохранением большей тяжести. Положительные объяснения не смешиваются с промежуточными ответами «не найдено». Проверяются ссылки и полное покрытие ID в каждом ответе; частичный результат не сохраняется как успешный. Прогресс показывает текущую часть/запрос, использованные токены всех запросов и повторной разметки суммируются в успешном результате.

Запросы последовательные. Время и стоимость больших анализов могут расти квадратично; остаются ограничения контекста, ответа и квоты OpenAI. Попарная проверка не гарантирует выявление зависимостей, которым нужен одновременный контекст трёх и более частей, и не заменяет экспертную проверку. Возобновление с последней успешной части пока не реализовано: повторный запуск заново обрабатывает документы и повторно расходует кредиты.

Источник контракта API: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [GPT-5](https://developers.openai.com/api/docs/models/gpt-5).

Ошибки 401, 429, недоступная модель, неполный ответ и ошибки в ссылках завершают запуск с понятным сообщением. Они не маскируются локальными результатами. Секрет не возвращается клиенту и не записывается в логи приложения.

## Ограничения и дальнейшее развитие

- Прототип без многопользовательской авторизации; Docker-порты доступны только на loopback. Перед внешним размещением нужны аутентификация, изоляция проектов, TLS и контроль доступа.
- SQLite и фоновые задачи FastAPI рассчитаны на один серверный процесс. Для масштабирования: PostgreSQL, очередь задач и отдельные worker-процессы.
- До 10 МБ/файл, один файл на каждую сторону («до» и «после»), 150 страниц/PDF, 4 000 строк и 600 000 символов/файл. Ограничений GPT-анализа на 450 абзацев и 600 функций нет: используется обработка частями. Повторная загрузка в заполненную сторону возвращает 409; явная замена через `replace_document_id` выполняется транзакционно после парсинга и проверяет актуальность ID. Старые многофайловые проекты сохраняются, но новый запуск требует ровно двух файлов.
- Сканам необходим внешний OCR. Автоматическая нумерация Word может отсутствовать в извлечённом тексте: тогда остаётся адрес абзаца. Сложные PDF-колонки и таблицы требуют проверки разметки.
- Лексическое сходство используется только как справочная метрика ближайшего фрагмента, не для принятия соответствий или выявления рисков.
- Карта структуры отражает преемственность названий и функций, а не юридически подтверждённую иерархию или факт создания подразделения.
- Внешние нормативные проверки и бенчмаркинг операторов не входят в текущий прототип.
